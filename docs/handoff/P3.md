**Decisions I made:**
- `TaskStub` lives on `TestCase` (per-case, like `human_task_outcomes`), not
  as a top-level list like `MockDefinition` — each case's stub outputs need
  to match that case's own `input`, so per-case scoping is what actually
  makes sense; a shared/global stub list would force every case to see the
  same canned output regardless of its own amount/vendor/etc.
- Spiff's synthetic Start/End/join wrapper tasks (`task_spec.bpmn_id is
  None`) are filtered out of `path`/`events` at the source rather than left
  in and ignored downstream — confirmed by hand this is the actual, reliable
  way to distinguish them (name-based heuristics would be fragile).
- Timeout/unresolvable-task/unparseable-artifact are three genuinely
  different outcomes and get different `ExecutionResult.status` values:
  `error` (timeout, faulted expression), `skipped` (unresolvable task or
  unparseable artifact -> `EXE-RUNNER-UNSUPPORTED`). Only the latter is a
  "not our fault" signal; a timeout might still indicate something worth
  investigating (e.g. an actual infinite loop in the artifact).
