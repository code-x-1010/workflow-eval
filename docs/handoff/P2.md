**Decisions I made:**
- **P2 will never emit an `element_id`-keyed `TaskStub`, nor an id-bound path
  assertion.** Element ids exist only in the artifact and testgen never sees
  it. The committed golden example uses ids throughout (`Task_autopay`,
  `Gateway_amount`) because P3 hand-wrote it from the shared fixture — correct
  for a D2 example, but *it is not shaped like what my generator will emit at
  D8*, and P3 is building their whole execution loop against it. Said so
  loudly in `0005`. Do not "fix" the example by reaching for ids.
- Proposed **`Assertion.path_match: exact | semantic`**, default `exact`. Without
  it, `must_traverse: ["the approval branch"]` gets compared against a list of
  element ids and produces a **false assertion failure** on a workflow that was
  fine. Default preserves today's behaviour so P3 needs no work until D7. This
  is the only `packages/**` change I asked for and it must land before the D2
  freeze or it never lands.
- Did **not** add `path_match` to the golden example yet — it's proposed, not
  accepted, and the default keeps the example valid either way. Add it once P3
  ticks `0005`.
