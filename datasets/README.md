# datasets/ — the eval corpus

Owned by **P2**. `datasets/corpus/` is the corpus the whole evaluation runs
against (`make eval` -> `scripts/run_corpus.py --corpus datasets/corpus`).

```
datasets/
  corpus/manifest.json              # provenance + ground truth. Read this first.
  corpus/<case_id>/prompt.txt       # the input under evaluation
  corpus/<case_id>/reference.bpmn   # what a competent implementation looks like
  golden/                           # human-labelled calibration sets (D7)
  build_corpus.py                   # regenerates corpus/ ; --check verifies it
  tools/                            # the node-tree DSL and the case definitions
```

## Rebuilding

```bash
python datasets/build_corpus.py           # write corpus/ and manifest.json
python datasets/build_corpus.py --check   # verify what is committed, write nothing
```

**Edit `tools/cases_*.py`, never `corpus/*.bpmn`** — the artifacts are generated
and a hand-edit is silently reverted by the next build. `--check` fails if the
committed corpus and the case definitions have drifted apart.

`--check` also re-emits and re-validates every artifact (unique ids, every
`sequenceFlow` ref resolves, exactly one start event, no unreachable element, no
exclusive split whose outgoing flows lack both a condition and a default), and
verifies every `expected_diagnostics` entry is a registered `SPEC-*` code. A
reference artifact with a dangling flow ref is worse than no reference artifact,
because every alignment score computed against it would be quietly wrong.

That last gateway check is not hypothetical: `contracts/examples/artifact.bpmn`
fails it today (`Gateway_amount`'s flows have neither), which is why P3 could not
run the shared fixture through Spiff. That defect is deliberate there. It must
not be accidental here.

## The two halves, and why the corpus is useless without both

| Provenance | n | Reference is | Prompt is |
|---|---|---|---|
| `reverse_generated` | 30 | ground truth — the prompt was written from it | unrealistically detailed |
| `hand_written` | 10 | **one reasonable reading**, not ground truth | what users actually send |

The reverse-generated half uses the charter's bootstrap trick: author the
artifact from a common process template, describe it in natural language, use
the description as the prompt. Cheap, and the reference genuinely is ground
truth. The catch is that a prompt written *from* a diagram names every step,
every actor and every threshold, so a generator scores well on all 30 without
ever being asked to handle a gap.

The hand-written half is where generators actually break. Those prompts are
short and missing at least one thing that cannot be invented: a trigger, a
threshold, a failure path, a volume bound, an approver. `manifest.json` marks
them `reference_is_ground_truth: false`. **Do not score alignment strictly
against those references** — an ambiguous prompt has several defensible
expansions and a generator that picks a different one has not failed. What is
being measured on those ten is whether `/v1/spec` raises the right `SPEC-*`
diagnostic instead of quietly inventing the missing detail.

`u10_automate_onboarding` ("Automate our onboarding process.") and
`c05_employee_onboarding` are the same request at 40x the specification. A
generator that produces similar output for both is not being driven by the
prompt.

## manifest.json

Per case: `provenance`, `under_specified`, `reference_is_ground_truth`,
`patterns`, `expected_diagnostics`, `notes`, and `prompt_sha256` /
`reference_sha256`.

- **`patterns`** are *derived from the emitted artifact*, not hand-tagged, so
  the coverage table cannot claim a pattern the corpus does not have. Cases also
  declare their intended patterns in `tools/cases_*.py`; `--check` asserts
  declared ⊆ derived. That check caught ten false tags on first run.
- **`expected_diagnostics`** is ground truth for the D5 sufficiency work: the
  `SPEC-*` codes `/v1/spec` should raise for that prompt. Registry and severity
  rules: `docs/decisions/0008-spec-sufficiency-code-registry.md`.
- **`prompt_sha256`** is the natural cache key. The charter's advice to
  content-hash every LLM call to disk on day one is not a week-2 optimisation —
  it turns a 40-minute corpus run into 40 seconds.
